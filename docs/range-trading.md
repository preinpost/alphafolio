# 박스권 반복매매

`range_trade`는 사용자가 선택한 봉 주기와 가격 범위에 따라 현물 매수와 매도를 반복하는 도구입니다. 전략은 챗에서 준비하고, 사용자가 확인 카드의 **[켜기]**를 눌러야 시작됩니다. 준비만으로 실제 주문이 나가지는 않습니다.

## 지원 범위

- KIS와 토스에서는 국내·미국 주식을 거래합니다. 주문은 정규장 거래 가능 시간에만 처리하며, 국내 종가 단일가 시간에는 새 주문을 내지 않습니다.
- Binance에서는 현물 USDT 거래쌍을 지원합니다. 선물, 레버리지, bStock, Binance 미국 주식 직접 거래는 이 도구의 지원 대상이 아닙니다.
- 종목과 주문 계좌, 봉 주기, 매수·매도 기준가, 회당 매수 규모, 로스컷, 매수·매도 비용률을 모두 확인합니다. 비용률은 0으로 자동 설정하지 않습니다.
- 기존 자동매매 기능과 마찬가지로, 해당 통화의 하루 매수 한도를 설정해야 전략을 켤 수 있습니다.

## 준비 예시

아래 비용률은 **호출 형식을 설명하기 위한 예시**입니다. 실제 계좌에 적용되는 수수료와 세금을 확인한 뒤 입력해야 합니다.

```json
{
  "action": "prepare",
  "symbol": "ETHUSDT",
  "market": "binance",
  "broker": "binance",
  "interval": "5m",
  "buyPrice": 2700,
  "sellPrice": 2720,
  "amount": 1000,
  "stopPct": 5,
  "buyCostPct": 0.1,
  "sellCostPct": 0.1
}
```

`amount`는 설정한 매수 비용률을 포함한 회당 예산입니다. 주식은 `shares`, 코인은 `qty`로 수량을 지정할 수도 있습니다. 세 가지 규모 입력 중 하나만 사용합니다.

고정 가격으로 손절하려면 `stopPct` 대신 `stopPrice`를 입력합니다. 두 손절 방식은 동시에 선택할 수 없습니다.

## 일반 매매

```text
매수 대기
  → 선택한 봉 종가가 매수 기준가 이하
  → 매수 체결 확인
  → 매도 대기
  → 선택한 봉 종가가 매도 기준가 이상
  → 매도 체결 확인
  → 다시 매수 대기
```

매수한 뒤에는 추가 매수하지 않습니다. 이 전략으로 매수한 수량만 매도하며, 계좌에 원래 있던 보유분은 매도 대상에 포함하지 않습니다.

매수 지정가는 매수 기준가 이하, 정상 매도 지정가는 매도 기준가 이상으로 제한합니다. 조건을 충족해도 호가가 달라졌다면 미체결로 끝날 수 있습니다. 각 체결 시도는 즉시 체결 방식으로 진행하고, 30초 이내의 기한을 적용합니다. 미체결 잔량은 취소하며, 같은 봉 신호로 주문을 중복 생성하지 않습니다.

## 비용을 포함한 로스컷

### 고정 가격

현재 최우선 매수호가가 `stopPrice` 이하이면 손절을 시작합니다. 손익 기록에는 비용을 포함하되, 고정 가격 조건 자체를 수수료에 따라 바꾸지는 않습니다.

### 평가손실률

`stopPct: 5`는 **비용을 포함한 예상 평가손익률이 −5% 이하**라는 뜻입니다.

```text
매입원가 = 매수 체결금액 + 매수 금액 비용
예상 순매도금액 = 현재 최우선 매수호가 × 전략 보유 수량 − 예상 매도 비용
예상 평가손익률 = (예상 순매도금액 − 매입원가) / 매입원가 × 100
```

기준 자산으로 납부한 수수료는 보유 수량에서 차감합니다. 이 비용을 원가에 다시 가산해 중복 계산하지 않습니다. 부분 매도 시에는 남은 수량에 원가를 비례 배분합니다. 이전 매매의 실현손익은 이번 매수분의 로스컷 기준에 합산하지 않습니다.

현재 구현에서는 Binance의 주문별 체결 내역으로 기준 자산과 USDT 수수료를 확인합니다. BNB 등 외부 자산으로 납부한 금액 비용을 확정하지 못하면 설정한 비용률로 추정합니다. KIS·토스의 금액 비용도 현재는 설정한 비용률로 추정합니다. 매도 전 비용은 아직 확정되지 않았으므로 항상 예상값을 사용합니다. 매도 비용률에는 해당 시장의 매도세 등도 포함해야 합니다.

체결 순수량을 확인하지 못했거나 전략 수량과 매도 가능 수량이 다르면, 수량을 추측해 주문하지 않고 전략을 일시정지합니다.

## 손절과 정지

로스컷은 일반 매매의 봉 주기와 별개로, **기본 5초 주기로 현재 호가를 조회**합니다. 사용자별 주문은 직렬 처리되므로 다른 체결이 진행 중이면 확인이 지연될 수 있습니다. API 요청 제한에 걸리면 Binance의 `Retry-After`를 준수합니다.

로스컷이 발생하면 다음 순서로 처리합니다.

1. 손절 상태를 먼저 저장하고 재매수를 차단합니다.
2. 전략 보유분을 매도합니다. 손절 지정가는 현재 호가 대비 최악 −2% 범위에서 냅니다.
3. 부분 체결이면 남은 수량을 계속 처리합니다. 가격이 회복해도 손절 상태를 취소하지 않습니다.
4. 매도를 마치면 전략을 종료하며 자동으로 다시 시작하지 않습니다.

거래소 최소 수량·최소 주문금액 미만의 잔량은 매도할 수 없습니다. 이를 매도된 것으로 기록하지 않고 별도 보유 수량과 원가로 남기며, 확인 화면과 알림에 표시합니다.

**일시정지는 로스컷 감시도 중단하며, 보유분을 자동 매도하지 않습니다.** 매매 대상으로 관리 중인 보유 수량이나 확인이 필요한 주문이 있는 전략은 삭제할 수 없습니다. 별도 기록된 최소 단위 미만 잔량만 남았다면 전략을 삭제할 수 있지만, 삭제해도 계좌의 잔량은 그대로 남습니다. 결과 모름 상태와 손절 종료 상태는 일반 재개 버튼으로 다시 켤 수 없습니다. 주문과 잔고를 브로커 앱에서 직접 확인해야 합니다.

## 운영상의 제한

이 기능은 거래소에 상주하는 손절 주문이 아닙니다. 서버 중단, 시세 조회 실패, 장외 시간, 유동성 부족 중에는 손절이 지연되거나 체결되지 않을 수 있습니다. 입력한 가격이나 정확히 −5%에서 체결되는 것을 보장하지 않습니다.

전략과 체결 기록은 기존 D1 저장소에 보관합니다. 서버가 재시작하면 진행 중이던 주문의 상태를 확인하고 잔량을 취소한 뒤 보고를 반영합니다. 같은 보고를 두 번 반영하지 않으며, 반복매매 복구 자체가 실패하면 감시를 시작하지 않습니다. 기존 서버와 같이 단일 서버 프로세스로 운영하는 것을 전제로 합니다.

## 코드 구성

| 파일 | 담당 역할 |
|---|---|
| `packages/broker/src/triggers/range.ts` | 순수 함수로 비용, 손익, 상태 전이를 계산합니다. |
| `packages/broker/src/triggers/range-tool.ts` | 입력을 검증하고 사용자 확인 카드를 준비합니다. |
| `packages/broker/src/triggers/tool-helpers.ts` | 감시 도구가 공유하는 시장 선택과 목록 표시를 처리합니다. |
| `apps/server/src/range-runner.ts` | 호가 감시, 리스크 검증, 주문 선기록, 체결 보고와 복구를 처리합니다. |
| `apps/server/src/order-runner.ts` | 기존 자동매매와 반복매매가 사용자별 직렬 큐를 공유하게 합니다. |

새 스키마나 테이블을 추가하지 않습니다. 반복매매 설정과 상태는 기존 `triggers.action` JSON에 저장하고, 체결 기록은 `trigger_execs`를 사용합니다. 무기한 전략은 기존 만료 컬럼과 호환되는 내부 날짜를 사용하며, 화면에는 ‘정지할 때까지 반복’으로 표시합니다.
