## 0. 한 줄 요약

**"채팅 앱에 대시보드가 붙은 구조"를 "에이전트가 화면을 그리는 하나의 캔버스"로 바꾼다.**
지금은 Chat / Portfolio / Journal / Ledger / Settings가 서로 다른 탭이고, 에이전트는 Chat 탭 안에서 텍스트와 확인 카드만 낸다. 다음 세대에서는 에이전트가 **모든 화면의 공용 입력층**이 되고, 답을 **텍스트가 아닌 살아있는 위젯**으로 낸다. 사용자는 그 위젯을 홈에 고정하고, 조작하고, 이어서 질문할 수 있다.

## 1. 현재 위치 (코드 근거)

| 영역 | 지금 있는 것 | 차세대에서 활용하는 방법 |
|---|---|---|
| `packages/protocol` | `UICard` 유니온(주문 미리보기·정정·조건주문·Binance 3종·MCP 확인·감시 확인), `text_delta`/`tool_start`/`tool_end`/`activity`/`watch_event` 스트림 | 이 "카드" 개념을 일반화해 **`ui.widget` 생성형 UI 프로토콜**로 확장 (§7) |
| 확인 카드 | 서명 토큰 + `expiresAt` + `warnings/errors`. [확인]이 실제 주문의 유일한 경로 | 안전 모델은 그대로 두고 UX만 바꾼다: 티켓형 카드, 영향 미리보기, 길게 눌러 실행, 만료 표시 |
| `/api/portfolio`, NetWorthChart, Allocation/Holdings/Currency 카드 | KIS·토스·Binance·수동자산 통합 잔고, 순자산 추이 | 트리맵·렌즈·What-if·어트리뷰션의 데이터 원천 |
| `/api/ledger` (D1), 일지 | 가계부·예산·매매 일지 | 하나의 **머니 타임라인** 이벤트 소스로 합친다 |
| 감시(Watch) + 반복매매 | `WatchConfirmCard`(백테스트 미리보기 포함), `watch_event` 푸시 | 앰비언트 알림, 홈 경고 위젯, iOS 라이브 액티비티 |
| Capacitor iOS | 웹뷰 셸 | 위젯(WidgetKit)·라이브 액티비티·햅틱은 네이티브 플러그인으로 |

**핵심 관찰:** 백엔드는 이미 "에이전트 + 이중 경로(자연어/REST가 같은 데이터)" 구조다. UI만 그 구조를 따라가지 못하고 있다. 즉 이 재설계는 **대부분 프런트엔드 + 프로토콜 확장**이고, 브로커·원장 도메인은 거의 건드리지 않는다.

## 2. 디자인 원칙

1. **에이전트는 레이어다, 탭이 아니다.** 모든 화면 하단에 같은 Agent Bar가 있고, 현재 보고 있는 맥락(종목, 기간, 필터)을 자동으로 첨부한다.
2. **답은 위젯으로 한다.** 숫자를 묻는 질문에는 숫자 위젯, 비교에는 차트, 실행에는 티켓을 준다. 텍스트는 설명할 때만 쓴다.
3. **근거를 드러낸다.** 생성된 위젯마다 "왜 이 위젯?"과 데이터 출처·시각을 붙인다. 숫자가 오래됐으면 오래됐다고 표시한다.
4. **돈이 움직이는 순간만 느리게 한다.** 탐색은 즉각적으로, 실행은 의도적으로 마찰을 둔다(길게 누르기, 영향 미리보기, 만료).
5. **한눈에 보이고, 파고들 수 있다.** 홈은 3초 안에 상태를 읽을 수 있어야 하고, 모든 숫자는 탭하면 분해된다(순자산 → 기여도 → 종목 → 거래 → 일지).
6. **하나의 시간축.** 매매·일지·지출·알림·수입은 결국 "내 돈에 일어난 일"이다. 따로 보지 않고 한 줄에 놓는다.
7. **한국 관례.** 빨강=상승/수입, 파랑=하락/지출 방향. ₩ 표기, 만 원 단위 축약은 선택 사항.

## 3. North Star 방향 3가지

### A. Agent Canvas — "에이전트가 그리는 홈" ⭐ 추천
- **개념:** 앱을 열면 아침/장중/장후 **브리핑**이 스트리밍되고, 텍스트 사이에 위젯(기여도, 경고, 예산 페이스)이 끼어 나온다. 위젯은 📌 고정 → 개인 대시보드가 된다. 고정 화면(포트폴리오·타임라인)은 "에이전트가 자주 그리는 위젯의 정규판"이다.
- **레퍼런스 결:** Perplexity(답 + 출처 + 후속 질문), Arc/Linear(⌘K, 키보드 우선, 조용한 크롬), Toss증권(큰 숫자, 짧은 문장, 친절한 톤), Copilot Money(인사이트 카드).
- **장점:** 기존 강점(에이전트·확인 카드·감시)을 정면에 둔다. 프로토콜 확장 하나로 웹·iOS·위젯이 같은 언어를 쓴다. 혼자 쓰는 앱이라 개인화 리스크가 낮다.
- **단점:** LLM 비용·지연이 홈 첫 화면에 걸린다 → 브리핑은 **서버에서 미리 생성 후 캐시**, 위젯 데이터는 REST로 즉시 채우는 하이브리드가 필수다. 위젯 스키마 설계가 성패를 가른다.

### B. Money OS Timeline — "모든 것은 이벤트"
- **개념:** 홈 자체가 무한 스크롤 타임라인(Things/Day One + 은행 앱 거래내역). 상단에 순자산 스파크라인, 아래로 거래·지출·알림·일지·AI 인사이트가 흐른다. 에이전트는 타임라인에 "인사이트 이벤트"를 끼워 넣는 작성자 역할을 한다.
- **장점:** 정보 구조가 가장 단순하다(사실상 1개 화면 + 필터). 오프라인 우선·동기화 모델과 잘 맞고, 가계부 사용 빈도를 끌어올린다.
- **단점:** 투자 분석(배분·리스크·What-if)이 2급 시민이 된다. 장중 투자 판단에는 약하다.

### C. Terminal Pro — "개인용 블룸버그"
- **개념:** Robinhood Legend 같은 데스크톱 멀티 패널 워크스페이스. 드래그 가능한 그리드, 차트·호가·보유·감시·채팅 패널, 키보드 단축키, 저장 가능한 레이아웃. 모바일은 별도 간소화.
- **장점:** 데스크톱에서 정보 밀도가 최고다. 반복매매·조건주문 같은 고급 기능에 어울린다.
- **단점:** 1인 앱 대비 구현량이 가장 크고, 모바일·iOS와 경험이 갈라진다. 에이전트가 "패널 중 하나"로 격하된다.

## 4. 정보 구조 (A+B)

```
┌ Agent Bar (전역, 맥락 자동 첨부)  +  ⌘K 팔레트 (이동·명령·종목·자연어)
│
├ ◎ 브리핑 홈        — 스트리밍 브리핑 + 고정 위젯 보드 + 제안 질문
├ ▦ 포트폴리오       — 트리맵(렌즈: 오늘/누적/섹터/통화) · 종목 드로어 · What-if · 어트리뷰션
│    └ 종목 상세 (드로어 → 전체화면): 차트, 내 거래 마커, 일지, 감시, 매수/매도
├ ≡ 머니 타임라인    — 매매·일지·가계부·알림·수입 통합, 필터 칩, 인라인 인사이트, 빠른 입력
├ ⇅ 주문             — 독립 화면이 아니라 "티켓" 오버레이 (어디서든 열림)
└ ⚙ 설정             — 계좌·MCP·감시 관리 (⌘K로 접근, 레일 하단)
```

탭 수: 현재 5개 → **3개 + 오버레이**. 채팅 탭은 사라지고 대화 기록은 ⌘K "대화"와 각 위젯의 출처 링크로 접근한다.

## 5. 핵심 화면

### 5.1 브리핑 홈 — [`prototypes/home.html`](prototypes/home.html)
- 큰 순자산 숫자(카운트업) + 기간 토글 + 영역 차트.
- **브리핑 블록:** 3~4문장, 핵심 수치 강조, 하단에 근거 출처·생성 시각.
- **생성형 위젯:** 문장이 끝날 때마다 해당 위젯이 아래 그리드에 생긴다(기여도 상위 5, 비중 상한 경고 + 리밸런싱 버튼, 식비 페이스). 각 위젯에 "왜 이 위젯?"과 📌 고정.
- 시간대별 모드: 장 전(밤사이 미장·환율) / 장중(급변·감시 근접) / 장 후(일일 결산) / 주말(주간 리뷰·가계부).

### 5.2 포트폴리오 딥뷰 — [`prototypes/portfolio.html`](prototypes/portfolio.html)
- **트리맵:** 면적=평가액, 색=오늘 또는 누적 등락(빨강/파랑 농도). 렌즈를 바꾸면 타일이 애니메이션으로 재배치된다.
- **종목 드로어:** 타일을 탭하면 우측에서 열린다. Agent Bar 맥락이 해당 종목으로 바뀐다.
- **What-if:** 환율·반도체·KOSPI 슬라이더로 순자산 영향을 즉시 계산한다. "환율 1,450원이면?"이라고 물으면 에이전트가 슬라이더를 움직인다(`#whatif`로 데모).
- **어트리뷰션 바:** 종목 선택 / 섹터 배분 / 환율 / 현금 드래그.

### 5.3 주문 확인 흐름 — [`prototypes/order.html`](prototypes/order.html)
- 에이전트의 툴 단계를 체크리스트로 보여준다(잔고 조회 → 호가 → 검증 → 토큰 발급).
- **티켓:** 매수=빨강, 매도=파랑 헤더. 큰 예상 금액, 수량·가격 인라인 편집(편집하면 **새 토큰 재발급**, 이전 카드 무효), 실행 후 비중·예수금 변화, 경고.
- **길게 눌러 실행(1.2초):** 진행 중 햅틱 틱, 키보드(Enter/Space 길게)도 지원. 만료 카운트다운, 30초 미만이면 경고색, 만료되면 비활성.
- 접수 후: 라이브 액티비티 미리보기(체결 진행), 일지 작성 제안(추천 문장·음성).
- **안전 불변식:** 실행 경로는 지금처럼 서명 토큰 하나뿐이다. UI 변경은 마찰과 가시성을 *늘리기만* 한다.

### 5.4 머니 타임라인 — [`prototypes/timeline.html`](prototypes/timeline.html)
- 월 요약(순자산 변화·지출·실현손익), 필터 칩, 날짜별 그룹과 일별 손익.
- 매매 아래에 일지가 붙고, 가계부 항목에는 입력 경로("에이전트 입력")가 표시되며, AI 인사이트가 인라인으로 들어간다.
- 맨 위 자유 입력: 자연어 한 줄이 가계부·일지·감시로 라우팅된다.

## 7. 기술 접근

### 7.1 생성형 UI 프로토콜 (`packages/protocol` 확장)
지금의 `UICard`(실행 카드)는 그대로 두고, **읽기 전용 위젯**을 별도 유니온으로 추가한다.

```ts
// 제안 — packages/protocol/src/widgets.ts
export type WidgetSpec =
  | { kind: "metric"; label: string; value: number; unit: "KRW" | "USD" | "%"; delta?: number; asOf: number }
  | { kind: "movers"; items: Array<{ symbol: string; name: string; contribution: number; pct: number }>; asOf: number }
  | { kind: "allocation"; mode: "treemap" | "sunburst" | "bar"; groupBy: "sector" | "currency" | "broker" | "symbol"; asOf: number }
  | { kind: "series"; metric: "networth" | "price"; symbol?: string; range: "1D" | "1W" | "1M" | "YTD" | "1Y" | "ALL"; markers?: "trades" }
  | { kind: "budget-pace"; category: string; month: string }
  | { kind: "threshold"; watchId: string }
  | { kind: "whatif"; shocks: Array<{ factor: "USDKRW" | "sector" | "index"; key?: string; value: number }> }
  | { kind: "timeline"; filter: TimelineFilter };

export interface WidgetEnvelope {
  type: "widget";
  id: string;              // 고정·갱신용 안정 ID
  spec: WidgetSpec;
  why?: string;            // "왜 이 위젯?"
  sources: string[];       // 근거
  pinnable: boolean;
}
```

- **원칙:** 에이전트는 *데이터가 아니라 쿼리*를 보낸다(`groupBy`, `range` 등). 실제 숫자는 클라이언트가 기존 REST(`/api/portfolio`, `/api/ledger`)로 가져온다 → 환각 숫자가 사라지고, 고정한 위젯은 계속 살아있다. `metric`/`movers`처럼 계산값을 직접 싣는 경우에는 `asOf`를 필수로 둔다.
- 에이전트 쪽에는 `ui_show_widget` 툴 하나를 추가한다(스키마 = `WidgetSpec`). 서버가 검증한 뒤 `widget` 메시지로 흘린다.
- 고정 위젯은 서버에 `pins` 테이블(JSON spec)로 저장해 웹·iOS·WidgetKit이 공유한다.

### 7.2 프런트엔드 스택
- **모션:** `motion`(구 framer-motion) — 레이아웃 애니메이션(트리맵 재배치, 드로어), `AnimatePresence`(위젯 등장). 숫자는 `@number-flow/react`.
- **데이터 시각화:** `@visx/hierarchy`(treemap/partition), `@visx/shape`, `d3-scale`/`d3-shape`. 기존 NetWorthChart는 visx로 이관한다.
- **⌘K:** `cmdk`.
- **상태/데이터:** TanStack Query(캐시·오프라인 persist·낙관적 업데이트), 서버 스냅샷은 IndexedDB.
- **iOS:** Capacitor `@capacitor/haptics`, 라이브 액티비티·WidgetKit은 Swift 소형 플러그인(App Group으로 스냅샷 JSON 공유).
- **디자인 토큰:** Tailwind v4 `@theme`에 프로토타입의 `shared.css` 토큰을 그대로 옮긴다.

## 8. 디자인 언어

- **타입:** Pretendard Variable(본문·UI), JetBrains Mono 또는 Pretendard tabular-nums(숫자). 스케일: 64/40/28/20/17/15/13/11. 큰 숫자는 letter-spacing −0.04em.
- **색:** 중립 따뜻한 회색 바탕(#f6f5f2 / 다크 #0c0c0f). 의미색은 상승 #e5383b, 하락 #2f6fed, AI 액센트 보라 #6b4eff(에이전트가 만든 것은 모두 보라 배지), 경고 앰버. 색만으로 의미를 전달하지 않도록 ▲▼와 ± 기호를 함께 쓴다.
- **형태:** 18px 라운드 카드, 아주 옅은 그림자, 경계선 최소화. 실행 카드만 22px로 더 크고 무겁게.
- **모션:** 기본 `cubic-bezier(.2,.8,.2,1)` 200~500ms. 등장은 rise, 재배치는 layout, 숫자는 카운트업. `prefers-reduced-motion`을 존중한다.
- **밀도:** 모바일은 넉넉하게, 데스크톱 ≥1280px은 12열 그리드와 우측 컨텍스트 패널. "Comfortable / Compact" 토글.
- **톤:** 짧은 해요체. 숫자 먼저, 해석은 그다음.

## 10. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 생성형 UI가 틀린 숫자를 보여준다 | 위젯은 쿼리 스펙 중심으로 두고 숫자는 REST에서 가져온다. 계산값에는 `asOf`·출처를 필수로 붙인다 |
| 브리핑 지연·비용 | 사전 생성 + 캐시, 저렴한 모델 라우팅(`agent-config/models.json`), 실패 시 위젯만 표시 |
| 주문 UX가 화려해져 실수가 늘어난다 | 토큰 경로는 불변. 길게 누르기, 편집 시 재발급, 만료 비활성, 매수/매도 색·문구를 이중으로 표시 |
| 탭 제거로 기존 습관이 깨진다 | M3~M5 동안 기존 페이지를 ⌘K에서 계속 열 수 있게 둔다 |
| 다른 에이전트의 apps/web 리팩터와 충돌 | 이 문서는 설계만 한다. M0는 리팩터 머지 이후에 시작한다 |
| iOS 네이티브 작업량 | M6를 선택 단계로 두고, 웹 PWA만으로도 비전의 80%는 성립한다 |

## 11. 사용자 결정 필요 사항

1. **방향:** A+B 조합(추천)으로 갈지, B 단독(가볍게)이나 C(데스크톱 터미널)로 갈지.
2. **채팅 탭 폐지:** 대화를 홈/Agent Bar로 흡수하는 데 동의하는지.
3. **브리핑 사전 생성:** 크론 LLM 호출 비용(하루 3~4회)을 감수할지.
4. **주문 확인 방식:** 길게 누르기만 쓸지, iOS에서는 Face ID를 추가할지.
5. **iOS 네이티브(M6) 우선순위.**
6. **폰트:** Pretendard + 모노 숫자 조합을 쓸지, Pretendard tabular 하나로 통일할지.
